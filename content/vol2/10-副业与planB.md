# 副业与 Plan B：什么值得做，什么纯消耗

## 1. 三十秒自检

- [ ] 你想做副业，但还没开始，因为"不知道做什么"
- [ ] 你的 Plan B 是"再学一门新语言/新技术"
- [ ] 你买过课，但没学完
- [ ] 你想做的副业和你现在的技能毫无关系
- [ ] 你不确定公司允不允许你做副业

打勾 ≥2 个，往下读。**第二条是最常见的一个误解，第五条是最容易被忽略的一个真实风险。**

## 2. 结论先行

**先破除一个误解：Plan B 不是"多学一门技术"，是一条随时能启动的通道。**

区别很大：

| 假的 Plan B | 真的 Plan B |
|---|---|
| 学一门新语言 | **有人知道你会这门语言，并且会在有需求时找你** |
| 考个证 | **你做过一次，验证过能变现** |
| 存一笔钱 | **有一条确定的备选收入路径（哪怕只够三个月）** |
| 关注了很多机会 | **你在某个圈子里是有名字的人** |

**核心判断：一个东西能不能算 Plan B，只看一个标准——它有没有被验证过（哪怕是小规模）。**

三类副业的真实投入产出（诚实版）：

| 类型 | 举例 | 真实情况 |
|---|---|---|
| **技能变现** | 接外包、做咨询、讲课程 | **启动最快、确定性最高**；缺点是有天花板，且本质是卖时间 |
| **内容输出** | 公众号、视频、技术专栏 | **前期投入极大、回报极慢**；优点是复利效应最强，且职业加持明显 |
| **产品化** | 工具、SaaS、小程序 | 潜在回报最大；缺点是失败率高，且需要非技术能力（产品、运营、销售） |

**给在职程序员的推荐顺序**：技能变现练手 → 内容输出积累沉淀 → 产品化当作长期实验。

## 3. 现在就做

| 时间窗 | 动作 |
|---|---|
| **今天** | 检查劳动合同：有没有竞业、有没有"不得在外兼职"条款（**这一步不能跳过**） |
| **今天** | 明确你做这件事的目的：是**练手艺**、是**增加收入**、还是**建 Plan B**？目的不同，做法完全不同 |
| **本周** | 做一次最小验证：**接一个能收费的小活**（见第 4 段的 90 天验证法） |
| **本月** | 如果走内容路线：完成第一期输出。**不要先买设备、不要先设计 logo** |
| **本月** | 如果走产品路线：先找到 3 个愿意付费的人，再写第一行代码 |

## 4. 可直接抄的话术 / 模板

### 90 天最小验证法（强烈建议照做）

```
第 1~30 天：验证有人愿意付钱
  - 目标：完成 1 笔交易，金额多小都行（哪怕是 500 元）
  - 动作：告诉 10 个朋友你在接 XX 类型的活；在 1~2 个渠道发布
  - 判断：如果 30 天内连一个询问都没有，说明需求或渠道不对，换方向

第 31~60 天：验证能重复
  - 目标：完成 2~3 笔，且至少有 1 个回头客或转介绍
  - 判断：重复出现，说明这条路说得通

第 61~90 天：验证效率
  - 目标：算清楚每笔花多少小时、时薪是多少
  - 判断：如果时薪低于主业的一半，这件事作为收入来源不划算，
          但如果它有其他价值（人脉、练手），可以继续当作 Plan B
```

**这套方法的价值在于：90 天花掉的是业余时间，不是辞职后的全部身家。**

---

**场景一：检查副业是否合规（必做的第一步）**

```
在劳动合同和员工手册里搜索以下关键词：
□ 兼职 / 副业 / 在外任职
□ 竞业限制 / 利益冲突
□ 保密义务
□ 知识产权 / 职务作品（你在公司做的东西，版权通常属于公司）
```

**如果发现限制条款**：
> 优先选择"不与主业冲突、不使用公司资源、不在工作时间"的形式（如内容输出、公开分享）。**接外包前务必确认清楚。**

**场景二：告诉别人你在接活（很多人不好意思开口）**

> 「我最近在接点 XX 方面的私活，如果你或者你朋友有需要，可以推荐一下我。
> 不急，随便问问就行。」

要点：**这就是全部的营销。** 大多数副业是从这样一句话开始的，不需要任何包装。

**场景三：报价（第一次报价最容易犯的错）**

> 不要报时薪，报**项目价**。给出固定总价 + 明确的范围。

```
报价模板：

项目范围：（明确列出做什么，不做什么）
交付物：
交付时间：
总价：XX 元（首付 XX%，验收后付 XX%）
修改次数：包含 X 轮修改，超出部分另计
```

要点：**先写范围，再报价。** 没有明确范围的报价，最后一定会变成无休止的免费返工。

**场景四：拒绝不合适的活（这比接活更重要）**

> 「谢谢你的信任。这块我看了一下，和我现在的方向不太匹配（/ 我的时间不太排得开），
> 怕做不好反而耽误你。我帮你介绍一位更合适的朋友？」

要点：**早期什么都接会毁掉你的时间和定价能力。** 拒绝三次之后，你会知道自己到底想做什么。

## 5. 五个常见错误

1. **没检查合同就接活**
   → 后果：这是本节的第一条，也是最严重的一条。违反竞业或兼职条款可能直接影响你的主业
   → 正确做法：**先查合同**。不确定就优先做与雇主利益无冲突的形式

2. **没验证就大量投入**
   → 后果：花三个月做了个没人要的产品；买了一套用不上的设备；注册了公司有了成本
   → 正确做法：**先收到第一笔钱，再投入。** 90 天验证法存在的意义就是这个

3. **什么都接**
   → 后果：时间被低价事务性工作占满，无法建立任何复利，且永远抬不起单价
   → 正确做法：**宁缺毋滥**。拒绝是建立定位的唯一方式

4. **低估时间成本**
   → 后果：算了钱没算时间。接了个 3000 元的活，花了 60 小时，时薪低于最低工资，还拖垮了主业的状态
   → 正确做法：**每次结束后记录实际工时，算出真实时薪。** 用[真实时薪工具](../../tools/real-hourly-wage/index.html)算一下

5. **把副业当成逃避主业的出口**
   → 后果：主业持续下滑，副业也不成气候，两头皆失
   → 正确做法：**先解决主业的问题**（参见[Burnout](09-burnout.md)和[跳槽时机](05-跳槽时机.md)）。副业应该是加法，不是逃生舱

## 6. 真实案例（脱敏）

**案例 A · 做成了的**

某后端工程师的副业起点非常简单：他告诉几个朋友自己在接性能优化的咨询。第一单收了 800 元，花了 6 个小时。第二单是被转介绍来的。一年后他每月有 1~2 单，收入约等于主业的 30%，更重要的是——**他在业内被知道了**。

**做对了什么**：起步极轻量（一句话 + 一个朋友圈），第一单金额小但完整交付，并且明确限定了一个非常窄的方向（只做 XX 类型的性能优化）。

**做错了什么**：早期接过一个范围不清的活，拖了两个月，最后算下来时薪极低。**他后来的定价模板就是从那次亏出来的。**

**案例 B · 纯消耗的**

另一位工程师投入大量业余时间做了一个工具类产品，做了四个月上线，用户不到 100 人，付费 0 人。

**做错了什么**：他先花了四个月做产品，**没有先验证有没有人愿意付钱**。如果他先用两周时间写个 landing page 或者先预售，能省下几个月。

**他的总结**：「我以为难点是把东西做出来，其实难点是让人知道并且愿意付钱。**技术是我最不需要担心的部分。**」

**案例 C · 最有价值的副业可能不赚钱**

有人持续写了三年技术文章，没有直接收入。但在他被优化的时候，两周内收到了四个面试邀请——**其中三个是文章的读者内部推荐的。**

这说明一件事：**副业的价值不只是那笔钱，更是它建立的外部可见度。**
