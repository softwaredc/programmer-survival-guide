# 被优化的 12 个早期信号

## 1. 三十秒自检

- [ ] 你最近被排除在新项目之外
- [ ] 你的汇报关系发生了变化
- [ ] 你的活开始被拆给不止一个人
- [ ] HR 突然找你"随便聊聊"
- [ ] 你发现招聘网站上出现了你的岗位
- [ ] 你的导师或支持者离职了

打勾 ≥2 个，往下读。**注意：任何单一信号都可能是巧合，但同时出现两个以上，就值得认真对待了。**

## 2. 结论先行

**最重要的一句话：优化不是突然发生的。**

公司在动手之前，通常已经完成了三件事：
① **降低依赖**（把你的活分出去、文档要你补齐）
② **准备证据**（绩效目标调整、开始记录问题）
③ **完成合法性与流程准备**（HR 介入、审批流程、补偿预算）

这三件事都会留下可观测的痕迹。**看到信号不等于一定会被裁，但等于你有时间提前准备——这才是这一节的价值。**

**看到信号后的正确反应不是恐慌，是做三件事：**

1. **开始更新简历**（不投，先准备）
2. **算清自己的现金流和赔偿口径**（见[现金流管理](../vol3/10-现金流管理.md)和[赔偿金怎么算](../vol3/02-赔偿金怎么算.md)）
3. **导出你需要的材料**（成果记录、代码贡献、文档——但**绝不拷走公司资料**）

## 3. 现在就做

| 时间窗 | 动作 |
|---|---|
| **今天** | 对照下面 12 个信号打分，**统计你命中了几个** |
| **今天** | 更新简历（先不投），并把今年的成果流水整理出来 |
| **本周** | 算清：如果被优化，你的赔偿数字是多少（用[计算器](../../tools/severance-calculator/index.html)） |
| **本周** | 盘点现金流，确认自己能撑几个月 |
| **本月** | **合法地**整理你的个人材料：成果记录、你的代码提交记录、公开分享过的东西 |
| **本月** | 开始维护对外联系（更新脉脉/领英，联系两三位同行） |

## 4. 可直接抄的话术 / 模板

### 12 个信号清单（逐项标记：○ 没有 / △ 存疑 / ● 明确有）

```
可信度【高】—— 这些几乎不会是巧合
□ 1. ● 招聘网站上出现了你的岗位（或 JD 与你的职责高度重合）
□ 2. ● 你的职责被明确拆给了两个人，且新人已就位
□ 3. ● HR 突然约你"聊聊职业规划/最近状态"，且你的上级不知情
□ 4. ● 你被要求限期补齐所有文档和交接材料

可信度【中】—— 需要结合其他信号判断
□ 5. ● 你被排除在新项目之外，理由是"先把手头的做完"
□ 6. ● 你的汇报线变了，新上级对你没有了解
□ 7. ● 你的审批权限 / 权限组被回收
□ 8. ● 你不在某个关键会议的名单里了
□ 9. ● 原本支持你的上级或导师离职了
□ 10. ● 你的绩效目标被突然拔高，或口径与之前不一致

可信度【低】—— 单看可能是正常现象
□ 11. ● 1on1 的频率明显变化（变多或变少）
□ 12. ● 团队频繁提到"架构调整""组织优化""降本增效"
```

**判断规则**：
- 命中任一【高】信号 → **立刻开始准备**
- 命中两个以上【中】信号 → **本周开始准备**
- 只有【低】信号 → 不必紧张，但可以顺手更新一下简历

---

**场景一：HR 突然约你聊天时的应对**

> 「好的，什么时间方便？是关于什么方面的内容方便先说一下吗？」

要点：**先问清楚主题，给自己留出准备时间。** 不要当场赴约。如果对方含糊其辞，你就更要准备——这通常意味着谈的是你不期待的事。

参加这类会议的三条纪律：**不表态、不签字、不争论**。只听，然后说「我需要时间考虑」。详见[被通知当天](../vol3/01-被通知当天.md)。

**场景二：被要求"把文档补齐"时**

> 「好的，没问题。方便问一下是有同事要接手，还是要做团队的知识沉淀？」

要点：**这个问题非常关键。** 如果是"有人要接手"，答案通常是前者。了解原因后你就清楚自己的处境了。

**顺手要做的一件事**：补齐文档这个过程，本身对你有利——它让你的工作变得可迁移。**这是少数几个"配合对你也有好处"的情况。**

**场景三：向可信的上级核实（谨慎使用）**

> 「我最近有点拿不准自己的方向，想问一下，你觉得我这边接下来这一年应该重点关注什么？
> 有没有什么是你觉得我现在做但团队不太需要的？」

要点：**不要直接问"我是不是要被裁了"**——这会让对方非常为难，而且大概率得不到真话。用上面的问法，对方如果知道情况，通常会给出暗示。

**场景四：准备期间如何不露痕迹**

```
□ 简历更新在私人设备或个人账号上进行，不要用公司电脑
□ 不要在公司网络下投递简历（多数公司有上网行为审计）
□ 不要向同事透露你在看机会 —— 消息传播速度远超你的想象
□ 不要拷走任何公司代码、文档、客户资料 —— 这是唯一一条绝对的纪律
```

## 5. 五个常见错误

1. **看到信号但说服自己"想多了"**
   → 后果：这是最常见的一种。因为承认这件事很不舒服，人会自动否认
   → 正确做法：**不需要相信最坏的结果，只需要提前做最坏的准备。** 准备的成本很低，不准备的代价很高

2. **开始消极怠工或摆烂**
   → 后果：这正好给了公司想要的证据（绩效问题），并且让你失去谈条件的筹码
   → 正确做法：**继续正常交付，同时私下准备。** 表现越好，你的谈判地位越强

3. **带着情绪质问上级或 HR**
   → 后果：对方会立刻切换到标准流程模式，所有弹性消失
   → 正确做法：**全程平静**。你的目标是拿到最好的结果，不是证明谁对谁错

4. **为了"自保"拷走公司资料**
   → 后果：这是本节最严肃的警告。可能构成侵犯商业秘密，后果远超你的想象，而且会影响你接下来的整个职业生涯
   → 正确做法：**只整理属于你自己的东西——成果记录（用数据描述，不带公司资料）、公开分享过的内容、你自己写过的总结**

5. **等到最后一刻才开始更新简历**
   → 后果：在最慌乱的时候做最重要的准备工作，质量最差
   → 正确做法：**简历应该是一个常态维护的东西**。每年至少更新一次，无论你有没有打算跳槽

## 6. 真实案例（脱敏）

**背景**：某中型互联网公司的后端工程师，工龄 5 年。

**他注意到的早期信号**：① 他被要求在一周内补齐三个系统的文档（之前两年没人提过）；② 他被移出了每周的技术规划会（理由是"这个会人太多了"）；③ 招聘网站上出现了 JD 与他职责高度重合的岗位。

**做对了什么**：他在看到第二个信号时就开始更新简历，并且算清了自己的赔偿和现金流。他**没有**降低工作质量——照常交付，甚至在补齐文档这件事上做得很认真（后来他发现这些文档在面试时帮了大忙，让他能把项目讲得很清楚）。

**做错了什么**：一开始他有两周在说服自己"想多了"，浪费了最好的准备窗口。

**结果**：三周后 HR 约谈。因为已经准备好了，他全程平静，只谈口径，最终拿到了符合法定上限的补偿，并在一个月内入职新公司。**中间没有一天失业。**

**他的总结**：「最有用的不是那三个信号本身，是我在第二周到第三周之间做的准备。那两周决定了后面三个月的从容。」
