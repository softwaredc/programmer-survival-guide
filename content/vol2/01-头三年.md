# 头三年：技术栈怎么长，才不是"三年经验一年用"

## 1. 三十秒自检

- [ ] 这一年你做的事，和去年几乎没有区别
- [ ] 你能熟练完成需求，但说不清自己解决了什么别人解决不了的问题
- [ ] 你写简历时发现三年的经历只能写三行
- [ ] 你不知道自己明年想成为什么样的人
- [ ] 你已经很久没有觉得"这个我不会，但我很想搞懂"

打勾 ≥2 个，往下读。**尤其是最后一条——它是所有信号里最准的一个。**

## 2. 结论先行

**判断你是在成长还是在重复，只有一个标准：**

> **过去一年里，你做过多少件"当时不会、需要学才能做"的事？**

如果答案是零，或者接近零，那你这一年大概率就是"一年经验用了一年"。

头三年的三个技术成长层次：

| 层次 | 表现 | 典型状态 |
|---|---|---|
| **会用** | 能在框架里写出能跑的代码 | 照着文档和已有代码能完成需求 |
| **会改** | 能在出问题时定位原因并修复 | 能看懂栈、能调性能、能改底层配置 |
| **会造** | 能在没有现成方案时设计出一个东西 | 能选型、能权衡、能为自己的决定负责 |

**大多数人卡在第一层，却以为自己在第二层。** 区分方法很简单：如果框架给你报错你能查，但让你**不用框架写一遍**你写不出来，那你在第一层。

**最重要的一句话**：三年后拉开差距的，不是谁写了更多代码，而是谁经历过更多"当时不会、硬着头皮搞懂了"的事情。

## 3. 现在就做

| 时间窗 | 动作 |
|---|---|
| **今天** | 写下过去 12 个月里，你做过但需要现学的三件事。**如果一件都写不出来，这是最重要的一个信号** |
| **今天** | 确认自己现在处于哪个层次（会用 / 会改 / 会造），写下来 |
| **本周** | 主动向主管争取一件"稍微超出你现在能力"的活。**在头几年，主动要活是被鼓励的** |
| **本周** | 选一件你日常在用但不理解原理的东西（比如某个中间件、某个网络机制），花一周搞懂它的核心原理 |
| **本月** | 完成一次输出：写一篇技术笔记、做一次团队分享、或提交一个开源 PR。**输出会暴露你真正的理解程度** |
| **本月** | 评估这家公司你还能不能学到东西（见第 5 段第 4 条） |

## 4. 可直接抄的话术 / 模板

**场景一：向主管争取更难的活（关键是让他没有风险）**

> 「我最近想提升一下 XX 方面的能力，这方面我经验还不太够。
> 后面如果有类似的事情，能不能给我一个机会试试？
> 我这边会保证不影响现有排期，做不完或者出问题我会第一时间同步你。」

要点：**主管不给新人难活的真正原因通常是担心延期，不是怀疑你的能力。** 你主动承诺"保证现有排期 + 第一时间同步风险"，就把他的顾虑消除了。

**场景二：让领导知道你在成长（不是邀功，是降低信息差）**

> 「上次那个 XX 问题，我查了一下原因，是 XX 导致的，我用了 XX 的方式解决。
> 我写了个简单的记录放在 XX，如果后面有人遇到类似的可以参考。」

要点：**这是轻量同步，不是邀功。** 多数主管不知道你这一年做了什么，因为他也在忙自己的事。**定期轻量的同步，比年底一次突击写材料有效十倍。**

**场景三：判断自己该不该离开（自我提问模板）**

```
□ 过去 6 个月，我有没有做过"当时不会"的事？
□ 身边有没有比我强、且我学得到的人？
□ 我做的事，明年是否比今年更复杂？
□ 如果我现在离开，简历上这一年能写什么？
□ 这里的业务是在增长、持平，还是收缩？

三个以上为"否" → 认真考虑换环境
```

**场景四：拒绝一个没有成长的"舒服"岗位**

> 「谢谢，不过我这边更想找一个能做 XX 方向的位置，希望这几年能把这块做深。」

## 5. 五个常见错误

1. **用"我很忙"代替"我在成长"**
   → 后果：忙了三年，能力和第一年没有本质区别，而市场上"三年经验"的期望远高于此
   → 正确做法：**每隔几个月问自己一次：我最近忙的这些事，明年还值钱吗？**

2. **只学"下一个项目要用的东西"**
   → 后果：技术栈被公司绑定，一旦行业方向变化或公司不行了，你会发现自己没有通用能力
   → 正确做法：区分**保质期短的知识**（某个内部框架、某个公司特有流程）和**保质期长的知识**（系统设计、网络、操作系统、调试能力、数据结构）。**后者投入产出比高得多**

3. **从不输出，只输入**
   → 后果：以为自己懂了，一开口讲就发现全是漏洞。**这是最容易被忽视的成长障碍**
   → 正确做法：写笔记、做分享、写文档。**输出的痛苦程度，就是你的真实理解水平**

4. **在一家学不到东西的公司待太久，因为"稳定"**
   → 后果：头几年最值钱的资产是成长速度，用稳定换掉了它，后面很难补回来
   → 正确做法：**头三年的稳定性不值钱，成长才值钱。** 稳定是你三十五岁之后才需要考虑的东西

5. **以为换个公司就能解决成长问题**
   → 后果：换了三家公司，做的事情一模一样。**问题不在公司，在你接活的姿态**
   → 正确做法：先问自己——在现在的公司，我有没有主动争取过？**如果答案是没有，那问题可能不在环境**

## 6. 真实案例（脱敏）

**背景**：两位同期入职某电商公司的后端工程师，起点相近。

**A（成长快）**：第一年完成了本职工作后，主动接手了没人愿意做的"老系统迁移"，过程中被迫搞懂了大量历史包袱和部署流程。第二年他成了团队里唯一能讲清楚那个系统全貌的人。第三年他开始参与方案设计。

**B（重复三年）**：三年里一直在同一个模块加需求，做得非常熟练，几乎不出错。第三年他想跳槽时发现：简历上能写的只有"负责 XX 模块的需求开发"，面试时被问到系统设计完全答不上来。

**差别在哪**：不在于谁更聪明，也不在于谁更努力——**B 比 A 可能还更辛苦**。差别在于 A 主动进入了"当时不会"的区域，而 B 一直在熟练区里重复。

**B 后来的做法**：他没有跳槽，而是在现公司主动申请转到一个新方向的组，用半年时间重新建立了"不会→学会"的节奏。**这也是一种解法——不一定非要换公司，但必须换做事的方式。**
