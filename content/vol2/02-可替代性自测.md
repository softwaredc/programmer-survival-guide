# 可替代性自测：换个人多久能接手你的活

## 1. 三十秒自检

- [ ] 你负责的东西，没有文档，或者文档严重过时
- [ ] 团队里只有你一个人知道某个模块的完整逻辑
- [ ] 你说不清自己这个季度创造了什么可量化的结果
- [ ] 你的工作几乎不需要和其他团队协作
- [ ] 如果明天你消失一个月，团队会很难受——但你不确定是因为"你"还是因为"没人接"

打勾 ≥2 个，往下读。**注意：第 1 条和第 2 条看起来像是"我很重要"，实际上它们是最危险的两个信号。**

## 2. 结论先行

**这一节要打破一个直觉：**

> **可替代性不是由你的能力决定的，是由你的工作被记录和被理解的程度决定的。**

很多人以为"只有我会"是安全感的来源。**恰恰相反——"只有我会"意味着：**
- 你没法被晋升（你走了没人能接）
- 你没法被调岗（你被困在这个位置上）
- 你成了单点故障，而管理层处理单点故障的方式通常有两种：**给你好处留住你**，或者**想办法消除这个单点**

而第二种往往比你以为的更常见。

真正难以被替代的人，特征完全不同：

| 看起来重要（实际危险） | 真的难替代 |
|---|---|
| 只有我知道这系统怎么跑 | 这个系统被完整文档化，而**我能设计下一代** |
| 我的活没人接得走 | 我持续在做**别人还没开始做的事** |
| 我很忙、很关键 | 我的产出**能被量化并且被上级看见** |
| 我和上级关系好 | 我在**跨团队的范围**里有影响力 |

**一句话总结：把自己做成"不可替代"，不如把自己做成"持续在创造新价值"。**

## 3. 现在就做

先做下面这套自测，拿到你的等级，再决定动作。

### 可替代性五级自测

**维度一 · 可交接性**（每一项 0~2 分）

```
□ 我负责的系统有最新、别人能看懂的文档
□ 如果不考虑能力，一个同级同事照着文档能在我离开两周内接手
□ 我主动做过知识传递（分享、Code Review、带人）
```

**维度二 · 角色独特性**（每一项 0~2 分）

```
□ 我在做的是别人没人在做的事（新方向、新技术、新问题域）
□ 我不只执行，我参与决定"做什么"和"为什么做"
□ 我的判断在团队里被当作有价值的输入
```

**维度三 · 产出可见性**（每一项 0~2 分）

```
□ 我能用数字说清自己今年的三个产出
□ 我的产出被团队以外的人知道
□ 我的工作成果在简历上能写成有说服力的三行
```

**维度四 · 网络连接**（每一项 0~2 分）

```
□ 我在团队之外有至少三个能说得上话的人
□ 有人会在我不在场时替我说好话
□ 如果我需要换工作，我有可以求助的人
```

**评分：**

| 总分 | 等级 | 含义 |
|---|---|---|
| **0~8** | 🔴 高危 | 你现在就很被动，随时可能被"优化"，而且求职时会很难 |
| **9~14** | 🟠 偏弱 | 有基础但缺少可见性，需要做下面的动作 |
| **15~20** | 🟡 中等 | 大多数人在这里。安全但不抗风险 |
| **21~24** | 🟢 健康 | 有选择权，可以主动决定下一步 |

也可以用在线版：[职业风险自测](../../tools/risk-check/index.html)

### 对应动作

| 时间窗 | 动作 |
|---|---|
| **今天** | 完成上面的自测，写下你的分数和等级 |
| **今天** | 如果维度一得分低（≤2）：**本周内**开始写你负责系统的第一份文档 |
| **本周** | 如果维度二得分低：主动争取一件事的**决策参与权**，哪怕只是参与方案讨论 |
| **本周** | 如果维度三得分低：**记录三件你有产出的事，并量化它们** |
| **本月** | 如果维度四得分低：约三个不同团队的人各聊半小时，**不是为了求职，就是认识人** |
| **持续** | 每季度重测一次，看分数是不是在涨 |

## 4. 可直接抄的话术 / 模板

**场景一：向上级申请参与更高层次的工作**

> 「我这边想多参与一些前期的方案讨论。
> 不只是接需求，我想理解我们为什么做这件事、以及有哪些取舍。
> 后面如果有类似的机会，能带上我吗？我可以帮忙做一些调研和方案的初稿。」

要点：**"帮忙做调研和初稿"是让他无法拒绝的开口方式**——你是在替他分担工作，不是在索要权力。

**场景二：主动提出做知识传递（这是把"垄断"变成"影响力"的合法方式）**

> 「我发现 XX 这块目前只有我比较熟，其实这是个风险——万一我哪天不在，没人能马上处理。
> 我想整理一份文档，再给团队做一次分享，把这块的知识传出去。
> 花的时间不会太多，我在这周的日常排期里做。」

要点：**把消除单点故障说成是"团队风险管理"**，这会让上级非常认可。**然后你会发现：当文档写完、别人能接手之后，你反而自由了**——可以调岗、可以晋升、可以做新的事。

**场景三：让你的产出被看见（不邀功的方式）**

> 「补充一个背景：上次的 XX 优化，上线之后 latency 从 P99 XX ms 降到了 XX ms，
> 大概省了 X 台机器。我在周报里写了详细的过程。」

要点：**先有数字，再说。** 不要说"我做了很多"，要说"从 X 到 Y"。

**场景四：跨团队连接（不求人时的建立方式）**

> 「我看到你们组的 XX 方案挺有意思的，方便约个时间聊聊吗？
> 我们这边也在做类似的事情，想听听你们的思路。」

要点：**信息型求助比请求型求助容易得多。** 你只是想学习，对方也更愿意说。

## 5. 五个常见错误

1. **把"只有我会"当成护城河**
   → 后果：被困在原位（无法晋升调岗），而且管理层会把消除这个单点当作目标
   → 正确做法：**把垄断变成影响力**——文档化、带人、做分享，然后去做下一个新东西

2. **努力但不可见**
   → 后果：这是最普遍的一种亏。你做了大量工作，但决策者不知道
   → 正确做法：**每周一次轻量同步**（见[头三年](01-头三年.md)第 4 段）。**可见不是邀功，是消除信息不对称**

3. **只向上管理，忽视平级与跨团队**
   → 后果：你的价值只有一个人背书；一旦这个人离开或变动，你失去全部支撑
   → 正确做法：**影响力的半径要大于你的汇报线**

4. **用忙碌代替价值**
   → 后果：加班最多的人往往不是最难替代的人，因为"忙"不等于"产出"
   → 正确做法：每季度问一次——**如果我这个季度做的事被清零，会有谁受影响？**

5. **不看行业，只看公司内部**
   → 后果：在一家公司很值钱，离开后发现这项能力在市场上不通用
   → 正确做法：**每年更新一次简历并投几次试试**（不必真去）。市场的反馈是最真实的外部校准

## 6. 真实案例（脱敏）

**背景**：某公司两位后端工程师，能力相当，同期入职。

**工程师 A · 走"垄断"路线**：他负责一个核心但老旧的数据同步服务，代码复杂且没有文档。他刻意维护这种独占性（不写文档、不带人），认为这让他不可替代。三年后团队要做架构升级，管理层的判断是"这块太依赖个人，必须重构"——他被安排去重构它，重构完成后这个模块标准化了，他被调去维护边缘系统。**他亲手消除了自己唯一的筹码，还是自己动手干的。**

**工程师 B · 走"创造新价值"路线**：她同样负责一块核心业务，但她在第一年就把系统文档写了，带了两个新人。之后她主动去做了一件团队没人在做的事——搭建数据质量监控。三年后她成了这个方向在多个团队里的对接人。

**差别**：A 在保护一个静态的位置，B 在持续创造新的价值。**静态的位置一定会被清理，持续创造的人不会被清理。**

**A 后来的总结**（他在一次复盘里说的）：「我以为我在建护城河，其实我在给自己挖坑，还给坑加了盖子。」
