# 简历：从 0 到 HR 愿意打电话

## 1. 三十秒自检

- [ ] 你的简历超过一页
- [ ] 你的技能栏写着"熟练掌握 XX"
- [ ] 你的项目经历读起来像课程作业
- [ ] 你投了 20 份以上几乎没回音
- [ ] 你的个人信息里有照片、身高、婚姻状况

打勾 ≥2 个，往下读。**第二和第三是最常见的两个，第五个是不该存在的。**

## 2. 结论先行

**简历的目标不是"写全"，是让人在三十秒内产生一个念头：这个人值得聊十五分钟。**

这意味着：

1. **一页纸。** 应届生和三年以内经验的程序员，一页足够。**超过一页不是资历深，是取舍能力差。**
2. **不写技能清单，写产出。** "熟悉 MySQL"毫无意义（每个人都会写），"把某查询从 2s 优化到 80ms"才有意义。
3. **每一个项目都要能经得起追问。** 面试官会顺着简历逐项深挖。**写上去的东西必须能讲三十分钟，讲不了就不要写。**

关于机器筛选（ATS）的实际情况：
很多公司会先用系统按关键词过滤。**所以岗位 JD 里的核心技术词要出现在你的简历里**——但不要堆砌，要自然地出现在你的项目描述中。

## 3. 现在就做

| 时间窗 | 动作 |
|---|---|
| **今天** | 把简历砍到一页。删掉所有"熟练掌握""了解""熟悉"这类没有支撑的描述 |
| **今天** | 用[简历体检工具](../../tools/resume-check/index.html)跑一遍，修掉能自动发现的问题 |
| **今天** | 删掉照片、身高、体重、婚姻状况、政治面貌（技术岗不需要） |
| **本周** | 把每个项目改写成："问题 → 我做了什么 → 结果（数字）" |
| **本周** | 找三个不同的人看你的简历，其中至少一个是在招人的工程师 |
| **投递前** | 针对每个目标岗位，把 JD 里的核心技术词自然地加进去 |

## 4. 可直接抄的话术 / 模板

### 技术岗简历骨架（复制后填空）

```
# 姓名
电话 | 邮箱 | GitHub（如有） | 所在地 | 求职意向：XX 工程师

## 教育经历
XX 大学 | XX 专业 | 本科/硕士 | 20XX - 20XX
（如果学校有优势就放前面；如果不占优，可以放到最后，但不要删）

## 项目经历

### XX 系统（个人项目 / 实习 / 课设改造）
一句话说清它解决了什么问题
· 做了什么：____（技术动作，不是"参与""负责"）
· 结果：从 X 到 Y（必须有数字）
· 技术栈：____
链接：GitHub / 在线地址

### XX 项目
（同上，2~3 个足够）

## 实习 / 工作经历（如有）
XX 公司 | XX 岗位 | 20XX.MM - 20XX.MM
· ____（问题 → 动作 → 结果）

## 技能
（不要写清单！改成嵌入项目里。如果一定要有，写成：）
语言：____  框架：____  其他：____

## 其他（可选）
· 开源贡献 / 竞赛 / 技术博客
```

### 项目描述的写法对比（最关键的一段）

```
❌ 差：
"基于 Spring Boot + MySQL 开发的在线商城系统，实现了用户管理、
商品管理、订单管理等模块，使用了 Redis 缓存。"

问题在哪：全是"实现""使用"，没有一件事是"你解决了什么别人解决不了的问题"。
这样的描述全市有几千份一模一样的。

✅ 好：
"在线商城系统（个人项目，GitHub XX star）
· 订单超卖问题：在压测中发现高并发下库存扣减有并发问题，
  改用 Redis 预扣减 + 异步落库，压测 500 QPS 下零超卖
· 首页加载 3.2s：定位到 N+1 查询，改为批量查询 + 本地缓存，降至 480ms
· 独立完成前后端与部署，日活峰值 XX"

差别在于：好的版本里每一个字都在回答"为什么是你"。
```

**写不出来怎么办**：如果确实没有数字，就用**对比**（"从 XX 变成 YY"）或**规模**（"支撑 XX 请求量"）。**实在什么都没有，说明这个项目还不值得写上去。**

---

**场景一：请人帮忙看简历（如何问才有效）**

> 「方便帮我看一下简历吗？我投了 XX 份没什么回音。
> 如果你用 30 秒扫一眼，第一反应是什么？有什么地方让你不想继续看下去？
> 不用客气，直接说。」

要点：**不要问"你觉得怎么样"**（会得到客套答案）。**问"哪里让你不想看下去"**（会得到真相）。

**场景二：面试邮件 / 投递附言（提高打开率）**

```
主题：应聘 XX 工程师 —— 姓名 —— XX 大学

您好，

附件是我的简历，应聘 XX 岗位。

简单说一下为什么我觉得合适：
· （一条与 JD 匹配的经历，带数字）
· （一条相关的技术点）

感谢您的时间！
姓名 | 电话
```

要点：**正文里放一两条最有力的钩子**，让 HR 打开简历后有理由继续看。

## 5. 五个常见错误

1. **简历上写"精通 XX"**
   → 后果：面试官会按"精通"来问。答不上来基本就结束了
   → 正确做法：**不写任何评价性形容词。让产出替你说话**

2. **贴照片和个人无关信息**
   → 后果：技术岗不需要这些，而且会引入无意识的偏见
   → 正确做法：**只留联系方式、GitHub、所在地、求职意向**

3. **项目全是大同小异的"管理系统/商城/博客"**
   → 后果：HR 一天看几十份完全一样的简历，你的那份被淹没
   → 正确做法：**做一个别人不会做的东西**。哪怕是解决你自己的一个小痛点。**独特性比完整度值钱**

4. **写了自己讲不清的技术**
   → 后果：面试官顺着问三层就露馅，而且会连带怀疑你其他内容的真实性
   → 正确做法：**写上去的每一行，都要准备好被追问三十分钟**

5. **一份简历投所有岗位**
   → 后果：既过不了 ATS 关键词筛选，也让 HR 觉得你是海投
   → 正确做法：**每个目标岗位微调一次**。把 JD 里的核心技术词自然嵌入你的项目描述

## 6. 真实案例（脱敏）

**案例 A · 改简历前后**

某同学投了 35 份简历，收到 2 个面试。他的简历上写着"熟悉 Java/Spring/MySQL/Redis"，项目描述是"实现了 XX 管理系统"。

改完之后：
- 删掉了所有技能形容词
- 三个项目改成"问题 → 动作 → 结果（数字）"
- 加了 GitHub 链接和一段在线 demo

**再投 15 份，收到 6 个面试。** 他的技术和之前完全一样。

**案例 B · 靠独特性突围**

另一位同学的项目不是商城也不是博客，而是一个给自己用的小工具（他嫌某个日常流程太麻烦，写了个脚本自动化）。这个项目的复杂度不高，但**面试时他讲得非常有热情，也让面试官记住了他**。他拿到了比技术更强的同学更好的 offer。

**他的总结**：「大家都做过商城，但只有我有这个东西。面试官也是人，他也想听到一点不一样的东西。」

**案例 C · 被层层追问问倒**

（这是一个常见教训的脱敏版本）有人在简历上写了"精通某某技术"，面试时被连续追问三个层次后答不上来。面试官后来在反馈里写："能力与简历描述不符"。**这个词比"能力不足"严重得多。**
