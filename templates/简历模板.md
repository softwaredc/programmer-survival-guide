# 技术岗简历骨架（可直接复制填空）

> 适用于：中国大陆互联网技术岗，应届生 ~ 三年经验。
> 原则：**一页纸，不写形容词，只写产出。**

## 填写规则（比模板本身更重要）

### 1. 一页纸

应届生和三年以内经验的程序员，一页足够。
**超过一页不是资历深，是取舍能力差。**

### 2. 不写任何评价性形容词

```
❌ 熟练掌握 Java / 精通 MySQL / 熟悉分布式系统
✅ 让产出替你说话
```

理由有两个：
- 「熟悉 MySQL」毫无信息量，每个人都会写
- 写了「精通」就要按精通的标准被追问，答不上来基本就结束了

### 3. 每个项目都要能讲三十分钟

面试官会顺着简历逐项深挖。**讲不清楚的项目不要写上去。**

### 4. 每一个描述都要有数字

```
❌ 使用 Redis 优化性能
✅ 定位到 N+1 查询，改为批量查询 + 本地缓存，首屏加载从 3.2s 降到 480ms
```

没有数字怎么办：
- 用**对比**：从 X 变成 Y
- 用**规模**：支撑 XX 请求量 / 日活 XX
- 实在没有：**说明这个项目还不值得写上去**

### 5. 删掉这些

```
□ 照片
□ 身高 / 体重 / 婚姻状况 / 政治面貌 / 籍贯
□ 「个人评价」这一段（几乎没人看，还占地方）
□ 跟教程敲的 demo
```

### 6. 针对每个岗位微调

很多公司先用系统（ATS）按关键词过滤简历。
**把 JD 里的核心技术词自然地放进你的项目描述里。**
不要堆砌——放进描述里，不是放进技能栏。

---

## 自检（投之前最后一步）

```
□ 一页
□ 没有一个"熟练掌握""精通"
□ 每个项目都有数字或对比
□ 写上去的每一行，我都能讲 30 分钟
□ 有 GitHub / 博客链接（并且确实有内容）
□ 电话和邮箱正确
□ 已针对这个岗位调整过关键词
□ 找三个人看过，问的是"哪里让你不想继续看下去"
```
