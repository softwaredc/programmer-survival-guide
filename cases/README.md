# 真实案例

这里收录社区投稿的**脱敏**真实经历。

---

## 投稿方式

在 GitHub **Discussions** 的「案例投稿」分区发帖（不是 issue，因为案例需要叙事空间）。

### 强制字段

```
时间：YYYY-MM（不需要精确到日）
城市：（可选，写到城市级别即可）
行业 / 公司规模：大厂 / 中厂 / 小厂 / 外企 / 体制内 —— 不写公司名
岗位与年限：如"后端 4 年"

发生了什么：（≤500 字）

我当时做对了什么：（至少一条）
我当时做错了什么：（至少一条）
如果重来我会怎么做：（至少一条）
```

---

## 三条否决线（命中即不收录）

1. ❌ **出现公司真名**，或可以通过描述识别出具体公司
2. ❌ **出现可识别的个人身份信息**（姓名、花名、团队代号、具体项目代号等）
3. ❌ **纯情绪宣泄**，没有"做对 / 做错"两面

> 我们不收吐槽。**每一份经历都同时有经验和教训，只写其中一面的投稿没有价值。**

---

## 为什么必须脱敏

- **保护你自己**：公开点名公司可能带来法律风险，也可能影响你未来的背调
- **保护这个仓库**：不做公司黑名单，是本项目长期存在的前提
- **保护读者**：脱敏后的案例才能提炼出通用经验，而不是变成一场八卦

---

## 文件命名

```
cases/YYYY-MM-<一句话主题>.md
```

示例：`cases/2026-10-谈判时只谈口径不谈情绪.md`

---

## 许可

投稿即表示你同意：
1. 你拥有该内容的著作权，或已获得授权
2. 你同意以 **CC BY-NC-SA 4.0** 许可发布
3. 你同意本仓库对内容进行编辑、合并、脱敏处理

详见根目录 [LICENSE](../LICENSE)。

---

## 审核流程

1. 在 Discussions 发帖
2. 维护者审核（不超一周）
3. 通过后由维护者脱敏整理成 `cases/` 下的文件，并在相关章节中引用
4. 你会在 PR 中被署名（如果你愿意）

---

> 最后一句：
>
> **分享你的经历，是这个项目对他人最有价值的部分。**
> 一份真实的"我当时做错了什么"，比十句建议有用。
