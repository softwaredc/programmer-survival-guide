```
  卷一 · 入场              卷二 · 在场              卷三 · 离场
 学生 / 应届 / 新人        在职 1–10 年            失业 / 转型中
       │                        │                        │
       └────── 断层一 ───────────┴─────── 断层二 ──────────┘
                                                         │
       └───────────────────── 再入场 ─────────────────────┘

     这三段不是三种人，是同一个人的三个时刻。
```

你今天是在职程序员，明天可能就在谈赔偿。你今天是学生，明年就在试用期里挣扎。
这份指南按**生命周期**而不是人群来写——因为每个阶段的人，都该提前看一眼下一个阶段。

## 每篇长什么样

所有章节强制使用同一套 8 段结构，这是防止内容变成"正确的废话"的唯一手段：

```
1. 三十秒自检        打勾 ≥2 个才需要往下读
2. 结论先行          没时间的人只读这 5 行
3. 现在就做          今天 / 本周 / 本月，三段动作表
4. 可直接抄的话术    被要求不得为空
5. 五个常见错误      每条写清：错在哪 → 后果 → 正确做法
6. 真实案例（脱敏）  必须同时有"做对"和"做错"两面
7. 延伸与依据        法条条号 / 数据来源 / 相关章节
8. 免责
```

**第 4 段（可直接抄的话术）不允许为空。** 这是本仓库的评审硬标准。

## 为什么可能可信

- 每篇标明最后更新日期；法条类章节设 90 天复核周期
- 法律内容只引法条原文与条号，不给个案意见
- 数据类内容必须标来源与时间，社区贡献数据标"非抽样，仅供参考"
- 案例一律脱敏，不点名任何公司

## 这份指南不做什么

诚实说明边界，比假装全能更有用：

- ❌ **不给个案法律意见** —— 只整理法条与通用口径，具体情况请咨询专业律师或法律援助
- ❌ **不点名公司** —— 不做公司黑名单，不做避坑榜，不接受含公司名的投稿
- ❌ **不做医疗 / 心理诊断** —— 只给识别信号与求助渠道
- ❌ **不做面试题汇总、不做技术教程** —— 那些有更好的项目
- ❌ **不承诺结果** —— 不写"这样做一定能拿到 2N""这样做一定能找到工作"
- ❌ **不评价宏观政策** —— 只写个人当下能做的事
